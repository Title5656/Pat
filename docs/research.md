# Pat: ห้องค้นข้อมูล

ฟีเจอร์ของ Pat ตัวเดิม: ใช้ Discord client, token, Gemini API key และ process/service เดิม ห้องคุยทั่วไปยังใช้ persona เดิม ส่วนห้องค้นข้อมูลมี persona ที่ตอบตามหลักฐานและความจำคำถามแยกตามผู้ใช้ ไม่มีบอทหรือ deployment ตัวที่สอง

## เปิดใช้งาน

เพิ่มค่าต่อไปนี้ใน Environment ของ Render service Pat เดิม หรือ `.env` ที่ root ของโปรเจกต์:

```dotenv
PAT_RESEARCH_CHANNEL_ID=ใส่_ID_ห้องค้นข้อมูล
```

ห้องนี้ต้องต่างจาก `PAT_CHAT_CHANNEL_ID` ถ้าไม่ใส่ `PAT_RESEARCH_CHANNEL_ID` ฟีเจอร์ค้นหาจะไม่เริ่มทำงาน ไม่ต้องเพิ่ม `RESEARCH_*` จากคู่มือบอทแยกเวอร์ชันก่อนหน้า และโปรแกรมไม่อ่าน `.env` ในโฟลเดอร์ `research-bot` อีกแล้ว

ใช้ `DISCORD_TOKEN`, `GEMINI_API_KEY`, `GEMINI_MODEL` ของ Pat ที่ตั้งไว้แล้ว ไม่ต้องสร้าง Application หรือ token ใหม่ การเรียก Gemini ของทั้งสองห้องใช้โปรเจกต์ API เดียวกัน

## ตั้งสิทธิ์ห้อง

1. เปิด Message Content Intent ให้ Pat ใน Discord Developer Portal หากเปิดเพื่อคุยกับ Pat อยู่แล้วไม่ต้องเปลี่ยน
2. ให้ Pat มี View Channel และ Read Message History ในห้องต้นทางของทุกเซิร์ฟเวอร์ที่ต้องการค้น
3. ห้องค้นข้อมูล: ให้ Pat มี View Channel, Read Message History และ Send Messages
4. ปิด View Channel ของ @everyone ในห้องค้นข้อมูล แล้วเปิดสิทธิ์ให้สมาชิกหรือ role ที่ต้องการใช้งาน

โปรแกรมตรวจความเป็นส่วนตัวของห้องตอนเริ่ม ก่อนรับคำถาม และก่อนส่งคำตอบแต่ละส่วน หากไม่ผ่านจะไม่โพสต์ข้อมูลค้นหา แต่ห้องคุยเดิมและ voice log ยังทำงาน เจ้าของเซิร์ฟเวอร์และ Administrator สามารถดูห้องได้ตามสิทธิ์ของ Discord จึงควรใช้เซิร์ฟเวอร์ที่ไว้ใจผู้ดูแล

สมาชิกทุกคนที่เห็นห้องค้นข้อมูลสามารถถามได้ และอาจได้รับคำตอบจากทุกห้องที่ Pat อ่านได้ ไม่ได้จำกัดตามสิทธิ์ดูห้องต้นทางของผู้ถามเอง ลิงก์ต้นทางจะเปิดได้เฉพาะผู้มีสิทธิ์ในห้องนั้น

## วิธีใช้

พิมพ์คำถามในห้องค้นข้อมูล เช่น “Alice นัดกินหมูกระทะวันไหน” หรือ “ในเซิร์ฟ Friends คุยเรื่อง deploy ไว้ว่าอะไร” Pat จะค้นข้อความที่เกี่ยวข้อง ตรวจข้อความจริงกับ Discord แล้วตอบพร้อมชื่อเซิร์ฟเวอร์ ห้อง ผู้พูด เวลาไทย และลิงก์ข้อความ

คำถามสำหรับดูข้อมูลโดยตรงไม่ถูกนำไปค้นเป็นคำสำคัญ:

- `เซิร์ฟเวอร์ Friends มีห้องไหนบ้าง` แสดงห้องข้อความที่ Pat อ่านได้เป็นรายการหมายเลข
- `ห้อง general มีข้อความอะไรบ้าง` แสดง 50 ข้อความล่าสุด โดยเรียงจากเก่าไปใหม่ภายในชุด
- `ขอดู 120 ข้อความล่าสุดในห้อง general server Friends` แบ่งผลเป็นชุดละไม่เกิน 50 ข้อความ
- `ต่อ` ดูชุดก่อนหน้า หรือ `ต่ออีก 100 ข้อความ` เพิ่มจำนวนที่ต้องการอ่าน
- แต่ละชุดระบุชื่อผู้พิมพ์ เวลาไทย และช่วงเวลาของชุด หากชื่อห้องซ้ำต้องระบุชื่อเซิร์ฟเวอร์ด้วย

- `!status` แสดงจำนวนข้อความและความคืบหน้าการเก็บประวัติ
- `!forget` ล้างประวัติคำถามเฉพาะผู้ถามในห้องค้นข้อมูล
- `!reset` ยกเลิกผลของคำสั่งเดิมที่ยังค้างและล้างประวัติ ห้องที่เลือก และตำแหน่ง `ต่อ` เฉพาะผู้สั่ง
- ความจำห้องค้นหาเก็บคำถามล่าสุด 6 ข้อต่อคนใน RAM และไม่ใช้คำตอบเก่าเป็นหลักฐาน
- ข้อความห้องคุยเดิมถือเป็นแหล่งข้อมูลต้นทางเหมือนห้องอื่น แต่ไม่แชร์ conversation memory หรือ persona กับห้องค้นหา

ทุกคำสั่งเป็น read-only ต่อ Discord ทุกเซิร์ฟเวอร์ ส่วนค้นข้อมูลไม่มี API สำหรับลบหรือแก้ไขข้อความ สร้างหรือลบห้อง เปลี่ยนสิทธิ์ เตะ หรือแบนสมาชิก หากขอการกระทำเหล่านี้ Pat จะปฏิเสธ `!reset` เปลี่ยนเฉพาะหน่วยความจำชั่วคราวภายในโปรเซสและไม่ลบดัชนีหรือข้อมูลบน Discord

## การเก็บข้อมูลและ deploy

ใช้ build/start เดิมได้: `npm ci` และ `npm start` ที่ root ของ repo, Node 24, service เดิม และ `/health` เดิม การ push/deploy จะอัปเดต Pat ทั้งสองโหมดด้วยกัน

ตัวแปรที่ไม่จำเป็นต้องเปลี่ยนสำหรับการเริ่มใช้:

```dotenv
PAT_RESEARCH_DATABASE_PATH=data/research.sqlite
PAT_RESEARCH_SYNC_INTERVAL_SECONDS=60
PAT_RESEARCH_PAGES_PER_CHANNEL=3
```

ฐานข้อมูล SQLite อยู่ในโปรเจกต์ Pat หาก deploy บน filesystem ชั่วคราวจะหายเมื่อ redeploy/restart ให้ใช้ persistent disk เช่น mount `/var/data` และตั้ง `PAT_RESEARCH_DATABASE_PATH=/var/data/research.sqlite` ใช้หนึ่ง instance ต่อฐานข้อมูล

บอททยอยดึงประวัติเป็นหน้าละ 100 ข้อความ มี checkpoint ทำต่อหลัง restart; รับข้อความใหม่ การแก้ไขและการลบระหว่างออนไลน์ อาจต้องรอการเก็บรอบแรกตามจำนวนห้องและ rate limit ของ Discord

## ขอบเขต

- ค้น guild text/announcement channels, active/archived threads ที่ Pat เข้าถึงได้ รวมโพสต์ใน forum/media channels
- ไม่อ่านข้อความใน DM, เนื้อหาไฟล์แนบ, รูปภาพ, embed หรือเสียงในโหมดค้นหา (ห้องคุยเดิมยังวิเคราะห์รูปได้เหมือนเดิม)
- ไม่เก็บข้อความในห้องค้นหาและข้อความจาก Pat เองเป็นหลักฐาน เพื่อไม่ให้คำตอบวนกลับมาอ้างกันเอง
- ใช้คำค้นไทย/อังกฤษและ SQLite FTS5 ร่วมกับคำค้นที่ Gemini ช่วยสร้าง ไม่ใช่ vector search หรือการรับประกันว่าค้นครบทุกข้อความ
- ต่อคำถามตรวจต้นทางสูงสุด 90 ข้อความ ส่งหลักฐานสูงสุด 6 ข้อความให้ Gemini และอ่านได้ถึง 4,000 ตัวอักษรต่อหลักฐาน
- การเปิดดูข้อความของห้องดึงข้อมูลจริงจาก Discord แบบ read-only ครั้งละไม่เกิน 50 ข้อความตัวอักษรและใช้ `ต่อ` เพื่อย้อนดูเพิ่ม จึงไม่ติดเพดานรวม 50 ข้อความ
- การแก้ไขหรือลบขณะ offline จะถูกตรวจแก้เมื่อข้อความนั้นเป็นผลค้น คำใหม่ในข้อความเก่าที่แก้ตอน offline อาจค้นไม่เจอจนกว่าจะสร้างดัชนีใหม่
- หากต้องสร้างดัชนีใหม่ ให้หยุด Pat สำรองฐานข้อมูล แล้วเลือก `PAT_RESEARCH_DATABASE_PATH` เป็นไฟล์ใหม่ก่อนเริ่มอีกครั้ง
- คำถาม ประวัติคำถาม และข้อความหลักฐานที่เลือกจะส่งไปยัง Gemini API ข้อมูลในดัชนีอาจมีข้อความที่ลบขณะ offline จนกว่าจะถูกตรวจซ้ำ จึงไม่ใช่ระบบ purge/retention ที่สมบูรณ์
